# Release 2 verification checklist

This checklist records the tested Wind pathway and the identity checks needed for a Release 2 publication. No Release 2 tag, DOI, date or final version has been assigned in this document. The immutable `v1.1.0` tag and its [version DOI](https://doi.org/10.5281/zenodo.22061119) remain the released baseline. Do not cite the Wind pathway as part of that historical archive.

For each release candidate, record the exact full Git commit, source manifest, generated artifact hashes, and test runtime. Workbench and calculator source-set hashes cover only their listed file subsets; they supplement the full Git source identity.

## Release verification

1. Record the exact source commit and manifest. Run `npm test` under the configured CI Node version, check the deterministic builds, and compare the generated browser and standalone identities with the published artifacts.
2. Reproduce the January and July source-to-output tables and figures using the [reproduction guide](independent_reproduction.md) and [worked case](wind_case_study.md). Replay the bundles, record any numerical or provenance differences, and resolve substantive discrepancies. Check the known limits; two Wind windows do not establish several physical environments.
3. Create the release-specific version, changelog entry, tag and citation/DOI record. Rebuild from the exact clean tagged source; run individual and bundle replay again. The tag, source commit, artifacts, citations and documentation must agree.
4. Verify the release DOI and attribution before publication. Keep v1.1.0 history unchanged. Record corrections and compatibility/deprecation effects in future releases.

This checklist does not assign a release tag or DOI. Release claims should match the verified source and artifacts.
