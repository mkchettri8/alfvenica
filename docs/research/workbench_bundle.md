# Pass 6 local Wind workbench and replay bundle

The **Wind workbench** tab accepts an already-prepared `WI_H1_SWE` CSV and its matching `org.alfvenica.interval-input / 1.0.0` JSON sidecar. The optional verified fit-attribute JSON enables only the accepted density-fit component of inertial-length uncertainty. The browser uses the same Pass 3–5 modules packaged by `build-research-browser.js`; the browser calculator bridge evaluates through the existing formula registry and `reproducible-export.js`. It does not add plasma equations. Files are read through the local File API; there is no upload, downloader, server state, or row-bearing URL.

The workbench shows declared source identity, the complete column map, retained and rejected row IDs/reasons, missingness, cadence and nominal gap diagnostics before calculation. It then shows the four accepted quantity summaries, per-row UTC series and warning IDs, a numerical two-length-scale SVG, and Pass 5's separate fit component, interval variation, window sensitivity, and model limitations. Empty or incompatible results remain unavailable. The SVG makes no wave-mode inference.

## Export and replay

`analysis.json` uses `org.alfvenica.wind-analysis-bundle / 1.0.0`. It embeds the prepared CSV text and sidecar, optional fit-attribute evidence, all intake rows with raw and normalized values, accepted/rejected IDs and QC, Pass 4 series/summary/compatibility/warnings, Pass 5 treatment and sensitivity states, derived plotting data, the exact SVG, a Methods draft, and source/build identity. The prepared CSV is bounded by the Pass 3 1 MiB limit; local replay has a 16 MiB bundle limit. Source CDF bytes are **not** embedded or rehashed by the replay command. A declared checksum identifies source bytes only; it is not a quality or scientific-correctness result.

Separate download buttons provide `prepared.csv`, `metadata.json`, `summary.csv`, `plotting-data.csv`, `figure.svg`, `methods-draft.md`, `README-replay.txt`, and, when supplied, `fit-attributes.json`. The scale figure is regenerated from the exported plotting rows' two length-scale columns; those rows also hold the four row-by-row numeric series. No ZIP or external web dependency is required.

From a checkout containing this development code:

```bash
npm run replay:analysis -- /path/to/analysis.json
```

Replay reimports the embedded CSV/sidecar and reruns the accepted Pass 4–5 modules. It compares QC, row states, every numeric series, formula inputs, warnings, compatibility, uncertainty, summaries, plotting rows, SVG, and Methods text. Numeric comparison is **relative 1e-12 and zero absolute** in binary64, matching the computational Pass 2 policy. Strings, IDs and statuses compare exactly. `MATCH` means result, implementation identity and runtime match; `MATCH_ENVIRONMENT_DIFFERS` means the calculation and implementation match but runtime differs; `PROVENANCE_MISMATCH` means results match while source/formula/application identity differs; `MISMATCH` means calculation, processing, uncertainty, or presentation data differ. Runtime-only difference is a successful replay; a changed result or implementation identity is reported. These outcomes establish computational reproduction, not scientific validation or source-file authenticity.

The workbench build identity is `SOURCE_SET_SHA256` over the listed Pass 3–6 source files, generated by the build process. It is separate from the Pass 2 calculator-core source identity and the declared Wind CDF checksum. No unverified Git commit, Release 2 version or DOI is claimed. The Methods draft cites the repository-verified v1.1.0 base software DOI, marks a future Release 2 DOI **PENDING / AUTHOR REVIEW**, and marks publication wording **AUTHOR REVIEW REQUIRED**. It does not generate conclusions.

[`examples/wind_pilot/replay.py`](../../examples/wind_pilot/replay.py) invokes the supported Node replay, then reads `plotting-data.csv` with optional pandas; `--plot` makes a simple Matplotlib figure from exported numbers only. Python contains no plasma calculation or archive downloader.

## Manual browser check

1. Prepare the accepted local CDF with `examples/wind_pilot/prepare_pass4_local_cdf.py`; verify its accepted file identity. Prepare fit-attribute evidence with `verify_pass5_uncertainty.py`. Neither script downloads data.
2. Open `index.html` or the generated `alfvenica_standalone.html` with network access disabled, choose **Wind workbench**, and select the local prepared CSV, sidecar, and optional evidence JSON.
3. Select **Inspect import and QC**. Confirm the accepted real interval shows 73 selected/retained and zero rejected rows, the H1 GSE map, and no independent H0 alignment. Review the assumptions; select **Run accepted analysis**.
4. Confirm four series each contain 73 calculated results, density-fit components are distinct from full unavailable measurement uncertainty, and both equal-time half windows contain 36 and 37 rows. Inspect the table, charts, SVG disclaimer, and Methods draft.
5. Download `analysis.json`, `plotting-data.csv`, `figure.svg`, and `methods-draft.md`. Run the replay command above from an isolated checkout/copy of the same source. Check keyboard focus, narrow layout, warning text, and that the browser network log shows no data transfer.

This local development workflow is bounded to the accepted Wind pilot. It does not establish total beta, measured total mass density, calibrated field errors, H0 alignment, a spectrum diagnostic, a physical mode, or independent scientific correctness.
