# Pass 3 prepared interval intake

`org.alfvenica.interval-input / 1.0.0` is the local CSV plus JSON sidecar contract implemented by [`interval-import.js`](../../interval-import.js). The module runs in Node/CommonJS or a browser context with the existing unit registry and `TextEncoder`. It imports **prepared** short `WI_H1_SWE` rows; it neither downloads a CDF nor evaluates a plasma formula. Run the [synthetic example](../../examples/wind_pilot/sample.csv) with its [sidecar](../../examples/wind_pilot/metadata.json):

```bash
npm run import:interval -- examples/wind_pilot/sample.csv examples/wind_pilot/metadata.json
```

The fixture is **synthetic test data, not NASA observations**. Its DOI identifies the archive product whose variable meanings it imitates; `dataOrigin: SYNTHETIC_TEST_DATA` and the synthetic source filename make its origin explicit. The accepted real Wind files, interval, and scientific meanings remain in the [Pass 1 specification](wind_pilot_spec.md), [variable dictionary](wind_variables.md), and [manifest](../../examples/wind_pilot/manifest.json).

## Sidecar requirements

| Part | Required declaration |
| --- | --- |
| `schema` | Exact name and version above. Other versions fail closed. |
| `source` | `mission: Wind`, `productId: WI_H1_SWE`, dataset DOI `10.48322/nasd-j276`, source file name, product version, and `dataOrigin` (`CDF_DERIVED` or `SYNTHETIC_TEST_DATA`). Optional lowercase 64-digit SHA-256 has `digestScope: SOURCE_FILE_BYTES_ONLY`. A declared hash is not recomputed by this importer and proves neither quality nor correctness. |
| `time` | `column: Epoch`, `scale: UTC`, `format: ISO_8601_UTC_MILLISECONDS`, `meaning: SWE_SPECTRUM_START`, nominal support 92 s, and a half-open requested UTC interval `[start,end)`. The nominal support does not claim exact per-row integration endpoints. |
| `columns` | Every CSV header has exactly one declaration: prepared column name, exact archive `sourceVariable`, stable intake `semanticId`, kind, archive unit, CSV unit, required status, and applicable species, temperature kind, thermal-speed convention, vector group/component/frame, fit-flag relationship, time support, fill values, null tokens, and source CDF valid range. An arbitrary prepared column name is allowed only when this mapping supplies the accepted meaning. |
| `processing` | Exact policy IDs for missing values, `fit_flag=10`, duplicate and ordering rejection, explicit units, GSE component preservation, and no second-stream alignment. A different or omitted policy fails before rows are read. |

The `source_record_index` prepared column is a nonnegative zero-based source-row index. It is **not** a Wind CDF science variable. `Epoch` is supplied as prepared ISO UTC text; its archive unit is CDF epoch milliseconds. Required scientific fields are nonlinear-fit proton density, trace and perpendicular proton thermal **speeds**, and H1 co-reported `BX/BY/BZ`. Optional complete GSE proton `Proton_VX_nonlin`, `Proton_VY_nonlin`, `Proton_VZ_nonlin` and the three matching density/speed fit-sigma columns may be declared and preserved. One optional velocity component without the other two fails metadata validation. Fit sigmas remain fit context; this importer performs no uncertainty propagation. The scalar thermal speed remains trace speed under Wind's `sqrt(2kT/m)` convention. It is not converted to temperature here.

For `CDF_DERIVED` input, each scientific numeric column must declare finite CDF `VALIDMIN`/`VALIDMAX` and their archive unit, with `source: CDF_VALIDMIN_VALIDMAX`. The importer checks rows against those **declared** bounds. Preparing a real sidecar requires reading the corresponding CDF attributes and verifying the original file/version outside this importer; no thresholds are guessed. The synthetic sidecar explicitly uses `validRange: null` and does not claim archive range verification. Different CDF versions require reinspection as specified in Pass 1.

## Row policy and trace

Timestamp text must exactly match `YYYY-MM-DDTHH:mm:ss.sssZ` and round-trip through UTC parsing. Local-time strings, offsets, malformed dates, duplicates, and out-of-order rows are rejected. Duplicate policy rejects the later occurrence; ordering policy rejects the offending row without sorting. Both checks examine parsed timestamps in original CSV order, including rows later rejected for quality. Rows outside the half-open requested interval are rejected. There is no interpolation or replacement.

The only accepted primary fit flag is integer `10`; `9` and all other values are rejected. `10.0`, blanks, and the archive fill `-128` are invalid flag representations. Scientific numeric cells use declared `-1e31` fill and empty/`null` tokens. They become explicit `null` in `normalized`, with a `FILL_TO_NULL` or `MISSING_TO_NULL` trace entry. A missing required field rejects its row; missing optional context remains unavailable. Non-finite or malformed numeric text rejects the row. Required proton density and both required thermal speeds must be strictly positive. A complete zero B vector is rejected without forming a magnitude. Vector components remain separate, with GSE frame and no coordinate transform.

Supported CSV units are deliberately limited. Density accepts `cm^-3` or `m^-3` and normalizes to the registry's `m⁻³`; magnetic components accept `nT` or `T` and normalize to `T`; speed components and fit sigmas accept `km/s` or `m/s` and normalize to `m s⁻¹`. The three archive-unit conversions use the explicit Pass 1 multiplication factors (`×10⁶`, `×10⁻⁹`, `×10³`), while target-unit names come from the existing unit registry. Each conversion performed by this importer generates a `CONVERT_UNIT` entry with raw value/unit and normalized value/unit. The archive unit must still match the accepted Wind variable; a prepared CSV unit differing from it requires a preparation note and generates `DECLARE_UPSTREAM_UNIT_CONVERSION` marked caller-declared and unverified. Prepared upstream conversion must preserve the declared `-1e31` fill token unchanged rather than scaling it into a plausible scientific value. A temperature unit cannot stand in for a thermal speed. Values and units in `raw` are never overwritten.

Each logical CSV row has a unique `sampleId` containing source filename, declared source index when valid, and prepared CSV row ordinal. The `vectors` view marks each declared vector `complete` or `incomplete` without replacing its components; an undeclared optional V is `not_declared`. Rejected rows remain in `rows` and `rejectedRows`, with `firstFailure` and all detected `rejectionReasons`; `retainedRows` contains only accepted rows. `firstFailureCounts` is mutually exclusive under the documented priority order in the module: timestamp/window/order, fit flag, missing/invalid scientific values, declared archive range, physical positivity/zero-vector, then source-row identity. `allReasonCounts` is overlapping by row. Missing fraction is missing **required scientific numeric cells** divided by `(all CSV data rows × six required numeric fields)`; it is null when there are no rows. The summary also gives selected, retained and rejected counts, disallowed flags, invalid-domain rows, duplicate/out-of-order counts, and retained-row median start-to-start cadence. `gaps.nominalGapCount`, `totalExcessBeyondNominalSeconds`, and `maxExcessBeyondNominalSeconds` derive from consecutive retained start-time separations as `max(0, separation − 92 s)`. These are **nominal timing diagnostics**, not verified uncovered physical time or exact per-spectrum integration coverage. Zero retained rows produce a null median; no sample count implies scientific representativeness.

`mappingTrace` records column-to-semantic mappings; each row has `raw`, `normalized`, `vectors`, and transformation events `NORMALIZE_UTC_TIMESTAMP`, `CONVERT_UNIT`, `FILL_TO_NULL`/`MISSING_TO_NULL`, and `REJECT_ROW`. No magnitude is calculated. The [minimal pandas handoff](../../examples/wind_pilot/prepare_with_pandas.py) writes an already-prepared DataFrame and caller-supplied CDF-derived metadata into this CSV and sidecar shape; the caller must verify that provenance and CDF attributes. It requires pandas only when run and performs no download.

Software-safety limits are **1 MiB CSV**, **64 KiB sidecar**, and **1000 data rows**. They are bounded local-processing limits, not scientific quality cutoffs. Every CSV header still requires an exact semantic declaration; unknown or duplicate columns fail. The result reports `alignmentStatus: NOT_PERFORMED_COREPORTED_H1` and `alignedPairCount: null`: H1 magnetic components are co-reported in the same source row, while no independent H0 MFI pairing was attempted. Null does not mean zero aligned pairs. Pass 1 question W1 about exact per-spectrum support remains open for that optional stream. Successful ingestion establishes only checks against declared metadata and row policy. It does **not** establish archive authenticity, scientific model applicability, measurement uncertainty, an interval diagnostic, or physical interpretation.
